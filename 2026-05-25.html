Aligned to Whom?

Every model lab is becoming an agent lab, DeepSeek nukes the cost curve again, and Dwarkesh asks the constitutional question that will define the next century of civilization.

📰 Hacker News 📬 Substack 🎙️ YouTube

The End of "Just a Model"

Something tipped this week. Greg Brockman, OpenAI's co-founder and President, said the quiet part out loud: "the model alone is no longer the product." This isn't a casual observation. Brockman helped build the most valuable AI company in the world on the back of model improvements — and now he's saying the game has changed. The moat has moved up-stack, to what Latent Space's AINews is calling the "model + harness + workflow + UI + memory + economics" stack.

The evidence is piling up fast. AI21, one of the original large language model pioneers, has shut down its model development team and is pivoting fully to agent products. DeepSeek — the Chinese lab that shook the world with V3 and V4 — has quietly announced it's forming its first-ever "Harness team." Even the companies that once scoffed at the idea of building on top of their own models are now racing to own the entire interaction surface. Latent Space's synthesis of this moment is sharp: it's not enough to be the smartest model in the room anymore. You need to be the smartest model attached to the right environment — the right memory layer, the right tool integrations, the right evaluation loops.

"The top-tier product needs model <> harness <> product symbiosis. The model alone is not the product." — Greg Brockman, OpenAI, as quoted in Latent Space AINews

There's a subtler and darker interpretation buried in this shift: if you can post-train a model to only meaningfully perform when paired with your closed-source harness, you've just invented a new kind of lock-in. The model and the API are increasingly just the loss-leader. The harness — and your proprietary understanding of what makes it work — is where the defensibility lives. OpenAI's latest Codex updates (remote computer use, plugin sharing, goal improvements, appshots) are all harness features, not model features. The product is the whole operating system now.

Cheap Intelligence, Expensive Silicon

While the product layer consolidates, the economics of the underlying hardware are telling a different story. A new analysis from Epoch AI dropped on Hacker News with 324 points and nearly 350 comments: high-bandwidth memory (HBM) now accounts for 63% of AI chip component costs, up from 52% in Q1 2024. The compute silicon — GPUs, TPUs, the actual arithmetic — is becoming a smaller slice of the cost pie. The bottleneck has moved to memory. This has enormous consequences: it means that the path to cheaper AI runs through HBM manufacturing, not just through better training recipes or architectural innovations. It's a supply chain story, not a research story.

Meanwhile, at the software layer, DeepSeek is continuing to apply downward pressure on inference costs in a way that makes Western labs uncomfortable. A new open-source coding agent called DeepSeek Reasonix hit Hacker News's front page with 467 points — it's an MIT-licensed terminal coding agent engineered around DeepSeek's prefix-cache architecture to keep token costs low across long sessions. MCP-first, plan mode, cache-first loop. It's a clean example of what happens when the model is cheap enough to build real products on top of without worrying about per-token economics. The permanent price cut to DeepSeek V4 Pro (made official last week) puts it at roughly $0.18/million blended tokens — about 19x cheaper than Claude Opus 4.7 on comparable tasks, according to independent benchmarks. This is "intelligence too cheap to meter" territory, and it's arriving faster than most people expected.

The two forces — expensive memory, cheap inference — are converging on an interesting prediction: the value will shift toward whoever controls the most memory-efficient architectures and the best caching strategies. Prefix caching, KV cache reuse, and quantization tricks are not academic optimizations anymore. They're the battleground.

Constraint Decay: Why Agents Keep Breaking

Against this backdrop of everyone racing to build agent products, a paper that landed on Hacker News this week should give pause to anyone shipping agents into production. The paper, "Constraint Decay: The Fragility of LLM Agents in Backend Code Generation", documents a phenomenon that practitioners have been noticing for months but nobody had a clean name for: as an agent's task depth increases — as it takes more and more steps — its adherence to the original constraints it was given progressively degrades.

The intuition is almost painful once you see it. An agent starts a coding task with clear instructions: use this library, don't modify this interface, maintain these invariants. Five tool calls in, it's still following them. Twenty tool calls in, they're starting to slip. Fifty calls in, the agent is generating code that violates constraints it was explicitly given at the start. It's not forgetting them in the sense of dropping them from context — it's that in the process of reasoning through a complex problem, the accumulated weight of intermediate state crowds out the original specification. The constraints decay.

"LLM agents exhibit progressive constraint decay during extended backend code generation tasks — constraints introduced at the start of a task are increasingly violated as task depth grows." — Constraint Decay (arXiv 2605.06445)

This is not a fringe edge case. It's an architectural property of how current LLM agents work. The 188-point Hacker News thread is full of practitioners recognizing the pattern from their own deployments. The fix isn't obvious — it likely involves some combination of constraint re-injection at intervals, formal verification gates, or better hierarchical planning. But the important takeaway is this: everyone building agent products right now is building on a substrate that gets progressively more unreliable the longer you ask it to work. "Trust but verify" isn't just a best practice — it's a structural requirement.

The Question We're Not Asking About AI

Dwarkesh Patel published an essay this week that cuts deeper than anything else in the AI discourse right now. The surface topic is the Anthropic vs. Department of War conflict — Anthropic refused to remove red lines around mass surveillance and autonomous weapons, the DoD threatened to designate them a supply chain risk, markets gave it a 74% chance of being reversed. But Dwarkesh uses this as a lens for a question that he argues is "maybe the most important question about what happens in the future with powerful AI systems — and we barely talk about it."

The question: To what or to whom should AIs be aligned?

Not "will AI be safe" or "when will we reach AGI." Those questions have absorbed nearly all of the public AI discourse. But the harder question — when an AI system is capable and deployed at scale, whose values does it reflect, who can override it, and under what circumstances — has been almost completely unexamined. And as Dwarkesh points out, this matters now, not in 20 years, because the DoD/Anthropic fight is exactly this question in miniature.

"In whose service should AI break the chain of command and even the law? Who gets to write this model constitution that will determine the character of these powerful entities that will basically run our civilization in the future?" — Dwarkesh Patel

The alignment question the field has been working on — "how do we make AI systems follow human intentions?" — assumes a single human whose intentions matter. But real-world deployment is a multi-principal problem. The model company embeds certain values at training time. The operator (a government, a business, a developer) has their own instructions. The end user has their own goals. And the AI itself, if it has genuine reasoning capabilities, may have something that functions like its own sense of what's appropriate. Anthropic's situation crystallizes exactly where these principals conflict: the government is one principal, Anthropic's training-time values are another, and the question of who wins is literally what the DoD/Anthropic fight is adjudicating.

Dwarkesh's deeper worry is about mass surveillance — not as a theoretical future risk, but as a near-term technical reality. The calculation is simple: 100 million CCTV cameras in the US, decent open-source multimodal models at $0.10 per million input tokens, a frame every 10 seconds at ~1,000 tokens each. Total cost: ~$30 billion per year today, ~$300 million by 2028, and dropping. The technical bottleneck to mass surveillance disappears within this decade. The only thing that will stand between a functional surveillance state and the legal architecture permitting it is political norm-setting — and AI companies drawing and holding lines in the sand are, however accidentally, doing that norm-setting right now.

This connects directly to the Project Glasswing findings that Anthropic announced this week: Claude Mythos Preview and partners found more than ten thousand high- or critical-severity vulnerabilities in essential software within a single month. AI is simultaneously the most powerful offensive security tool ever built and the most powerful defensive security tool ever built. Whoever controls it, controls the security posture of everything built on software — which is everything.

Stateless Agents and the Maturing Protocol Stack

One piece of infrastructure news worth flagging: the MCP (Model Context Protocol) 2026-07-28 release candidate dropped this week, and it contains a significant architectural change. The protocol is going stateless: no handshake, no session ID, any request can hit any server instance. The RC also introduces first-class extensions — MCP Apps and Tasks — and cleaner auth and deprecation policies.

This is a meaningful operational shift for anyone running agent infrastructure. Stateless MCP means easier horizontal scaling, simpler load balancing, no sticky-session headaches. It's the kind of change that doesn't make headlines but quietly unblocks a lot of production deployments. The harness layer is maturing in exactly the ways that enterprise infrastructure needs it to. As model labs race to own the product stack, the underlying protocol work is keeping pace.

What This All Means

  1. The product layer is consolidating around harnesses. Every major AI lab is now building the full stack — model, tools, memory, workflow, UI. Pure model companies are becoming a rarer breed. If you're building on top of a model API without also building harness differentiation, your moat is thinner than you think.
  2. Cost compression is real and accelerating, but hardware is the new bottleneck. Inference is approaching free. Memory (HBM) is now 63% of AI chip costs and isn't compressing as fast. The companies that win on economics will be those that figure out memory efficiency — caching, quantization, retrieval-augmented approaches that minimize memory pressure.
  3. Constraint decay is a structural problem, not a bug. Agents get progressively less reliable as tasks get longer. Any serious production deployment needs to treat this as a first-class concern: constraint re-injection, intermediate verification, formal gates. "It worked in the demo" is not a reliability argument.
  4. The alignment question that matters isn't technical — it's political. The DoD/Anthropic conflict is a preview of the governance fights that will define the next decade. Who has the right to override an AI's trained-in values? What norms prevent AI from being weaponized for mass surveillance or political control? These questions need public debate now, while the technology is still at a stage where norms can actually stick.
  5. Glasswing is the canary in the coal mine for AI-powered security. Finding 10,000+ critical vulnerabilities in a month is not a PR win — it's a warning. The same capability that finds these vulnerabilities can be used to exploit them. The security industry's defensive orientation needs to catch up to this reality faster than it currently is.
